# Humanoid pose modes

The existing target-TRS bake reproduces individual clips, but blending already retargeted bone rotations differs from Unity's Humanoid blending. Real Mixamo idle/run/wave comparisons measured up to 0.148 m joint error and 12.95 degrees local rotation error with that representation. This is a pose-space difference, not a rendering defect or a problem solved by increasing the sample rate.

`AnimationBakeSettings.HumanoidPoseMode` now offers an opt-in `PreciseMuscles` path. Existing settings remain `BakedTargetTRS`; they are not silently migrated.

The precise bake retains the authored 95 muscle channels and target-normalized body position/orientation. It does not reconstruct muscle inputs from a retargeted skeleton. Runtime sampling and muscle blending run as Burst ECS jobs. The separate `AnimationSystemDOTS.Humanoid` assembly converts the blended human pose into rig-local bone poses through the public, unbound `HumanPoseHandler(Avatar, string[])` API. It uses an Avatar asset reference and shares one solver per rig inside each World. It creates no GameObject, Animator, PlayableGraph or scene bone hierarchy. Unity documents the [unbound pose conversion API](https://docs.unity3d.com/cn/6000.0/ScriptReference/HumanPoseHandler.GetInternalAvatarPose.html).

The final Avatar conversion is a managed ECS system on the main thread. This is **not an all-Burst Humanoid retargeter**. An isolated Editor measurement of 1000 native retarget calls for the 70-joint target measured 4.09 ms median / 4.70 ms p95 over 100 warm batches. That excludes sampling, ECS buffer copies, skinning and rendering, and is not a scene or Player benchmark.

`HumanoidRuntimeParityTests` compares actual ECS buffers and model poses against a native manual Mixamo graph. Dense fixtures cover 240 phases at three weights. Measured maximum joint errors were 0.583 mm for three-way blending, 1.563 mm for masked upper-body override/additive, and 14.533 mm for full-body additive; measured local rotation error was 0 degrees. Full-body additive translation is therefore within the 2 cm / 2 degree acceptance boundary, but is not identical to native. Additional fixtures cover Root, Head, arm, fingers and Root+Body masks, and transformed authoring roots. These results establish the pose backend, not complete Animator graph, transition or IK compatibility. Graph conversion remains separate work in the [implementation plan](Designs/2026-11-06-animator-validation-plan.md).

Blob schema 3 contains muscle/body channels, authored additive references and compiled human masks. Additive requests require an explicit reference pose on the source clip. Cache identity includes the reference asset/content/time, pose mode and converter version; animation libraries own deep copies. `AvatarMaskBakePipeline` compiles body-part weights and Root ownership. A separate muscle snapshot preserves the hips of the root-owning layers while upper-body layers change the final pose; this may require a second native conversion. Baking normalizes the isolated preview root so authoring placement is not applied twice. Mixing Generic clips into a precise Humanoid library is rejected. Callers must inspect `HumanoidBodyPose.Result` for unsupported or invalid requests.

SubScene integration verifies the Avatar asset reference, actual pipeline evaluation, actor placement, unload/reload and absence of companion Animators. A cold Editor restart is required after changing the serialized blob layout: hot-session native type caches produced invalid old-layout reads during development. This does not require changing existing controller logic.

The three new validation scenes are still under implementation. The existing 02 and 04 samples retain their prior target-TRS configuration. Ragdoll is not implemented in this milestone; its feasibility and separate physics adapter are described in the [approved scene design](Designs/2026-11-06-animator-validation-design.md).

The controller layer checkpoint adds native comparisons for masked override/additive, partial/zero Direct layer history and a Root-off layer followed by a Root+Body layer. These traces measured up to 1.114 mm / 0 degrees; the tested full additive controller trace measured 6.112 mm / 0 degrees. Root-off additive trees support moving source clips. Moving-root additive playback with Root enabled requires root-motion support and is rejected during controller conversion; use an in-place source or disable Root in the mask. The complete checkpoint passed 179 Editor/Sandbox and 51 Runtime tests. Both existing 1000-character scenes also produced 3000 successful finite palettes with zero runtime Animators. These checks do not establish new-scene performance.

Controller interruption history now stores the previous/pre-step/frozen 95-muscle stream and body pose per layer before retargeting. It does not freeze retargeted bone transforms. Three real Mixamo traces cover repeated Current/Next interruptions and a masked layer; their measured maximum was 0.176 mm / 0 degrees. This is a fixture-specific accuracy measurement, not new-scene performance. Restore both Humanoid controller history buffers when replaying an authoritative snapshot.
